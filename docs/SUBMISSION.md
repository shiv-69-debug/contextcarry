# Submission checklist

**Deadline: 6 October 2026, 3:15 PM IST (Asia/Kolkata).**

[Open the event submission page](https://events.mlh.com/events/15105-hacktoberfest-hack-day-nashik-x-msc-kbtcoe)

## Working project

- [ ] The main flow works from a clean start.
- [ ] The model actually participates in the demo.
- [ ] At least one realistic example is ready.
- [ ] Failures and limitations can be explained honestly.
- [ ] Evidence is based on real runs, not estimated or invented results.

## Repository and documentation

- [ ] Public GitHub repository is accessible in a signed-out browser.
- [ ] README has the final project name, problem, approach, and selected track.
- [ ] README includes exact setup and run instructions.
- [ ] README documents testing or reproducible evaluation steps.
- [ ] README identifies AI tools, models, libraries, and reused code.
- [ ] Open-source licence is included (required for Track 2).
- [ ] Required third-party attributions and licence notices are retained.
- [ ] No API keys, credentials, or private example data are included.
- [ ] Starter TODOs are replaced where relevant to the project.

## Track-specific checks

### Best Use of Gemma 4

- [ ] The actual Gemma 4 model used is identified.
- [ ] Its essential contribution is visible in the working project.
- [ ] Any advertised comparison or measured improvement is reproducible.

### Best Open-Source AI Project

- [ ] Open-source or open-weight AI is an important part of the system.
- [ ] Installation, running, testing, and licensing are documented.
- [ ] If submitting an Agent Skill, it follows the Agent Skills specification.
- [ ] If submitting a harness, the original implementation or meaningful changes are clear.

## Demo and final submission

- [ ] Live demo link or short demo video is accessible.
- [ ] README links to the demo.
- [ ] Registration/check-in requirements are confirmed on the event page or with venue staff.
- [ ] Project details and intended challenge selection are entered on the event page.
- [ ] Submission is completed before 3:15 PM IST.
- [ ] Confirmation is checked and retained.

## Suggested two-minute demo script

The website does not specify a presentation duration; adjust this rehearsal outline to the organizers' instructions.

1. **0:00–0:20 — Problem:** who needs this and what is difficult today?
2. **0:20–1:10 — Working flow:** show a real input, the model doing its work, and the useful output.
3. **1:10–1:35 — Technical contribution:** explain the key implementation choice and what you built yourself.
4. **1:35–1:50 — Evidence:** show one measured result or comparison and one limitation.
5. **1:50–2:00 — Close:** show the repository and state the next improvement.
